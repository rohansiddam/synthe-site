Getting started

Clone the repo, run the checker against the example packets. Two minutes, no dependencies beyond Python.

$ git clone https://github.com/rohansiddam/Synthe.git && cd Synthe

$ python3 src/handoff_check.py examples/v03/packets/valid-signed.json --registry examples/v03/registry.json --workspace examples/v03/workspace

ACCEPT claim recorded

The check order

The checker runs these checks in order and stops at the first failure, so the reason code tells you exactly which link broke.

  1. StructureRequired fields, schema version, and field shapes. missing_field:id, bad_schema_version
  2. IdentitySender and receiver resolve in the registry; aliases must use the canonical id. unknown_agent:from
  3. SignatureEd25519 over domain-separated canonical JSON. signature_invalid, signature_signer_mismatch
  4. IdempotencyThe key must not be completed, reserved, or in an unknown state. duplicate_idempotency_key
  5. FreshnessThe handoff must not be expired. handoff_expired
  6. AuthorityPlanned actions against tools, forbidden lists, signed approvals, and budget. approval_missing, budget_exceeded
  7. EvidencePinned hashes recomputed against workspace files. evidence_not_verbatim, artifact_hash_mismatch

Core concepts

The packet

A handoff is a typed JSON packet: who sends, who receives, what was done, what evidence backs it, and what the receiver may do next. Nothing free-form.

The registry

Each receiver holds a registry of agent identities and public keys. A packet's signature is verified against the registry before anything else is checked.

The ledger

Every ACCEPT is recorded with an idempotency key. The same work can never be claimed twice, even across restarts.

Approvals

Actions a packet declares must be covered by a signed approval. A bad or missing approval is a REJECT with the reason named, not a silent pass.

Reason codes

Every verdict names its reason. The complete reference, grouped by check stage:

Structure
missing_handoffThe packet has no handoff object.
missing_field:nameA required field is absent or empty, e.g. missing_field:purpose.
bad_schema_versionOnly schema 0.1 is accepted.
bad_on_failureon_failure is not one of reject, retry_with_budget, escalate, request_human.
planned_actions_missingThe receiver's policy requires declared planned actions.
Identity
unknown_agent:from / :toThe sender or receiver is not in the registry.
alias_not_canonicalAn alias was used where the canonical agent id is required.
Signature
signature_missingReceiver policy requires a signed packet; none present.
signature_malformedThe signature block is not an object with a sig string.
signature_alg_unsupportedOnly Ed25519 is accepted.
signature_signer_mismatchThe signature's signer does not match the packet's from.
signature_key_unknownNo Ed25519 key on record for the signer.
signature_invalidThe signature does not verify: the packet was altered after signing, or the wrong key was used.
Idempotency
duplicate_idempotency_keyThis handoff was already completed.
idempotency_key_reservedThe key was claimed but the effect was never confirmed; reconcile before redispatch.
unknown_outcomeThe key was claimed long ago and never completed; the receiver may have crashed mid-effect.
Freshness
bad_expires_atacceptance.expires_at is not a valid timestamp.
handoff_expiredThe handoff expired before it was checked.

approval_missingAn action that needs approval has none recorded.
approval_expiredThe covering approval expired.
