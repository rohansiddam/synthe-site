Quick start

Prompt mode

Improve your agent’s prompt

On your default branch, in the repo:

npx synthe@latest init

Using Claude Code, Codex or Cursor? Tell it: Set up Synthe in this repo. Run npx synthe@latest guide and follow it. Or add the agent skill: npx skills add synthelabs/synthe.

Solve mode

Improve anything a command can score

Write a first problem file (npm or pytest projects), then run it:

npx synthe@latest problem init
npx synthe@latest solve synthe.problem.json

Try it first in one minute, with no key: clone github.com/synthelabs/synthe, then run npx synthe@latest solve examples/date-regex/problem.json in it.

What you need

  • Node 20 or later.
  • For prompt mode: a GitHub repo you can admin, with GitHub Actions turned on, and the GitHub CLI, signed in with gh auth login.
  • For Solve mode: a git repository with your files committed. Synthe works on a checkout of your last commit. --pr also needs the GitHub CLI.
  • Your own model key: Anthropic, or any OpenAI-compatible API (OpenAI, Gemini, Groq, OpenRouter, Together, or a local Ollama or vLLM). No key? Setup offers providers with a free tier. Prompt mode saves the key as the repo secret SYNTHE_ANTHROPIC_KEY for Anthropic, or SYNTHE_API_KEY for another provider.
  • With Claude Code or Codex as Solve mode’s proposer, you need no key: it runs on your own login.

Set it up

On your default branch, in the repo, run npx synthe@latest init. Before it spends anything, setup checks that the GitHub CLI is signed in, that you can admin the repo, that you’re on the default branch, and that your prompt file matches the copy on GitHub.

Then it asks for your key, which prompt to improve if it finds more than one, what your agent should get better at (one sentence), up to five real messages your agent has had (optional), and whether to merge improvements on its own. It proposes three checks, and shows how it marks a few replies so you can fix a check’s wording.

Setup writes synthe.json, .synthe/scenarios.jsonl, .synthe/attacks.jsonl and the workflow .github/workflows/synthe.yml, commits them as “Add Synthe”, pushes, and starts the first round.

It also saves your key as a repo secret, and changes two GitHub Actions settings for the whole repo: the default token for every workflow becomes read-only, and Actions may create and approve pull requests. If your other workflows need write access, give them their own permissions.

Another provider? Run npx synthe@latest init --base-url https://api.openai.com/v1 with your provider’s OpenAI-compatible address, or paste its key when setup asks. Setup asks what each model costs, so it can stop at your budget.

Merge settingAutomatic merges land on your default branch. If that branch deploys your app, a win goes live. Choose review to approve each one.
SharingNew installs share run details with the Synthe team by default; setup shows a notice and doesn’t ask. Run setup with DO_NOT_TRACK=1, or set "share": "none" in synthe.json at any time. What is shared

How it finds your prompt

A .md or .txt file whose name contains prompt, system or instructions; or a string of at least 40 characters in a TypeScript, JavaScript or Python file, assigned to a name with one of those words. Prompts can be up to 20,000 characters. If it finds no prompt, setup asks for the path. If it picks the wrong file, move your prompt to its own file, such as prompt.md, and run setup again.

Checks and rules

Checks say what a good reply does, in plain sentences: up to five, of up to 300 characters each. They decide every test: the reply that fails fewer of your checks wins, and an AI judge decides only when both fail the same number.

Rules (guardrails) are what a reply must never do. A change that breaks a rule your prompt kept is never merged.

Policy is your business rules, copied from your prompt at setup, so the judge knows what is allowed. Setup also writes about ten attack messages that try to override your prompt; a change that fails one your prompt passes is never merged. That is a basic check, not a security test.

Test messages

Setup writes up to 80 test messages to .synthe/scenarios.jsonl: 40 Synthe learns from (train) and 40 it keeps hidden (holdout). The part of Synthe that writes changes never sees the hidden ones. Add your own, one per line:

{"id": "s99", "input": "Can I return shoes I wore once?", "expected": "Explains worn items can't be returned and offers an exchange if they're faulty", "split": "train"}

expected describes a good answer in a sentence. The file needs both splits, and at least 5 train rows.

You can also mark a few cases "split": "vault". No round ever reads them. At the end of a run, npx synthe vault compares your prompt with the one the run started from on them, so you can see whether the gains carry to cases nobody picked winners on.

Each round

A round is one GitHub Actions run with three jobs. Write proposes two changes, each one or two exact edits. Score has your prompt and each change answer every learning message, then runs the best change on the hidden messages and the attacks. Decide applies the merge rule; it is the only job that can write to your repo, and it holds no model key.

Each finished round starts the next. A run stops after 12 rounds, after 3 rounds in a row with no winner, or when the budget is spent ($3 by default, checked before each round). An hourly schedule is only a backup; GitHub often skips scheduled runs.

The merge rule

min_improvement
Ahead by at least 2 points out of 100 on the learning messages, and on the hidden ones.
max_p
On the learning messages, wins against losses pass a sign test at p ≤ 0.05: at least 5 wins to 0.
holdout_max_p
On the hidden messages, p ≤ 0.1: at least 4 wins to 0, or 6 to 1.
guardrails
No new break of a rule your prompt kept, and no attack failed that your prompt passes.
noise_margin
After a merge, the old prompt keeps competing. If it wins by more than 3 points at p ≤ 0.05, Synthe puts it back.

Auto or review

In auto mode, a win is squash-merged into your default branch right away. In review mode, its pull request stays open and rounds pause, making no model calls, until your team merges or closes it. If branch protection needs a review, Synthe leaves the pull request open even in auto mode.

The report

The run keeps one issue in your repo, “Synthe: prompt report”, updated after each round. It leads with how often your checks pass on the hidden messages, then shows what changed with an undo hint, why a round didn’t win, what to do next, every round with its cost, the details for reviewers, and what the run did not test.

Each win’s pull request has the diff, why it won, a before and after example, and a warning to check any amount, time limit, email or link the change added. A record of each round, with hashes and scores but no text, is kept on the synthe/state branch; npx synthe verify checks one.

From your terminal, npx synthe status shows the headline and npx synthe changes shows the latest rounds.

Run Solve mode

Solve mode improves any files that a command can score: code in any language, configuration, documents and data. It never changes your working tree.

npx synthe@latest solve synthe.problem.json
  1. It makes a scratch checkout of your last commit, on a new branch, synthe/solve-<name>-<n>.
  2. It runs the guards. If one fails before any change, the run stops: fix the guard first.
  3. It measures the starting score.
  4. Each round, it asks the proposer for changes, applies them, runs the guards, measures, and keeps or undoes each one.
  5. It stops when the proposer has nothing more, at budget.max_rounds (6 by default), max_calls or max_usd, or after 3 rounds in a row that keep nothing.

The keep rule. With a noisy measure, a change must win on the first runs, then win again on fresh runs of both versions. With an exact measure, any change in the right direction is kept. With split.holdout, a change must also win on held-back data that the proposer never sees.

What it refuses. A change to a file outside artifact, to a protect file, to a file that the measure, guard or proposer commands use, or to the problem file. Test files and test-runner files in a measured folder need an exact artifact path. The reason names the path, and no file changes.

Press Ctrl-C at any time: Synthe stops its commands and removes its scratch checkout.

The problem file

A JSON file in a folder inside a git repository. Paths in it are relative to its folder. npx synthe@latest problem init writes a first one for npm (node:test) or pytest projects; npx synthe@latest problem check FILE checks one field by field.

FieldDefaultWhat it does
nameNames the branch, the output folder and the history
goalOne plain sentence; the proposer gets it
artifactThe files Synthe may change
protectFiles it must never change, even inside artifact
measure.commandA command whose last printed number is the score
measure.directionhigher or lower
measure.runs3Runs for each measurement; 1 only for an exact measure
guardsCommands that must still pass after a change
split.holdoutfalseAlso keep a change only if it wins on held-back data
proposera modelA coding agent, a model, or your own command
budget.max_rounds6Rounds per run; max_calls and max_usd cap calls and dollars
candidates1Proposals in each round; the round keeps at most the best one

No command can print a number? Measure with a judge: it compares outputs case by case, both ways round. npx synthe measure draft writes the judge’s cases and rubric from good and bad examples, and checks the judge against your labels.

Proposers

  • A coding agent, { "agent": "claude" } or { "agent": "codex" }: Claude Code or Codex on your own login, with no API key. It runs in a temporary folder that holds only the artifact files.
  • A model: Anthropic, or any OpenAI-compatible API, with your own key.
  • Your own command: it reads one JSON object (the goal, the files and every earlier attempt) and prints the proposed edits.

Every attempt is saved in your git folder and sent to the proposer on the next run, so it does not repeat an idea.

Results and more

Kept changes are commits on synthe/solve-<name>-<n>. Read them with git diff HEAD...synthe/solve-<name>-<n>, and merge the branch if you agree. If nothing was kept, there is no branch. result.json and report.md go to .synthe/solve/<name>/: why it stopped, the starting and final scores, every attempt with its reason, and the calls, tokens and cost.

OptionWhat it does
--prOpens a pull request with the evidence
--resumeContinues a run that was stopped
--record, --replayRecords a real run’s model calls, then replays them for free
--seed NRepeats a run whose measure uses random cases
npx synthe queue, npx synthe tickRun Solve jobs on a machine that can restart at any time

The public repo has three examples that run with no key, in examples/, and a GitHub workflow template, templates/synthe-solve.yml.

Run improve mode

Improve mode raises a built-in number in a JavaScript or Python repo, such as tests passing or bundle size, with no problem file. For anything else, use Solve mode.

In a clean checkout, on a branch that matches GitHub, run npx synthe@latest improve and answer its four questions, or pass them as flags; it asks for anything you leave out:

npx synthe@latest improve --goal "Accept every valid email at signup" --metric test-pass --mode review
FlagDefaultWhat it does
--goalWhat to improve, in a sentence
--metricasks, from what your repo can measuretest-pass, pytest, bundle-size, build-time or custom
--commandFor custom: the command to run, with --label, --unit and --direction higher|lower
--guardasks; Enter keeps your testsThe regression check every change must pass, or none
--modeasks; Enter means reviewauto merges the pull request; review leaves it for you
--rounds6From 1 to 20
--budget1.50Dollars, from 0.25 to 20
--protectA path it must never edit; repeat for more
--lessonsclaude or agents also writes what it learned to CLAUDE.md or AGENTS.md
--listShows the metrics this repo can measure, and changes nothing

It works in throwaway checkouts, so your working tree and branch are never touched. When it finishes, it pushes one branch and opens one pull request, only if something won. Both model calls use claude-sonnet-5-5, or your provider’s models.writer. It reads your key from SYNTHE_API_KEY or SYNTHE_ANTHROPIC_KEY.

Rather have your own coding agent make the change? npx synthe improve --handoff measures your code and prints a task card, with no model calls. Commit the change, then npx synthe submit measures it and opens the pull request only if it wins.

Metrics

MetricMeasuresRuns
test-passTests passing in npm test; higher is better3
pytestTests passing in python -m pytest -q; higher is better3
bundle-sizeBuilt JS and CSS, gzipped; lower is better1
build-timeTime for npm run build; lower is better3
customYour command; the last line of output that is a number3

It measures your current code first, and your regression check must pass on it. A change is kept only if the number moves the right way by more than the spread between runs, and your regression check passes, if you set one. With a tests metric, no test that passed before may fail. Then it has to win again when measured a second time. Each command has 10 minutes.

What it never edits

Tests and their fixtures; benchmark and metric folders; .github/; .env*, config files, Dockerfile and Makefile; dependency and project-settings files; hidden files; files named in your metric or check command; anything you --protect; and Synthe’s own files. Each round it picks up to 5 files of up to 50 KB, and makes at most 8 edits and 200 changed lines.

You can keep editing your prompt. After Synthe changes it, pull before you edit.

Stop, undo or remove

Stop: npx synthe stop. A round already running finishes; no new one starts. npx synthe restart starts it again.

Undo a change: click Revert on its pull request, or run npx synthe undo N. In review mode, close the pull request.

Remove it: run npx synthe stop. Delete synthe.json, .synthe/ and .github/workflows/synthe.yml (and synthe-diagnostics.yml if you have it), and the synthe/state branch. Delete the SYNTHE_ANTHROPIC_KEY or SYNTHE_API_KEY secret, the “Synthe: prompt report” issue, and the synthe/ branches. Then check the two Actions settings setup changed: nothing sets them back.

Solve mode leaves only what you keep: its synthe/solve-<name>-<n> branches, .synthe/solve/ in your repo (add .synthe/ to .gitignore), and its history in .git/synthe/solve/.

Improve mode changes your branch only through its pull request, which adds .synthe/improve-lessons.md. Its settings stay in .git/synthe-improve.json, which git doesn’t track.
