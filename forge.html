    How the check works

    Six links, checked in order. The first broken link names the verdict.

    1. 1. Sender in registry. The sender must be known, so there is a key to check against. unknown_sender
    2. 2. Signature valid. Recomputed over the signed envelope and compared. signature_invalid
    3. 3. Evidence pinned. Every file hashed against its pin. evidence_hash_mismatch
    4. 4. Approvals cover actions. Approvals are separate signed credentials; each is verified. approval_missing, approval_signature_invalid
    5. 5. Plan intact. Steps hashed against the committed plan. plan_tampered
    6. 6. Not a replay. The idempotency key must be fresh. duplicate_idempotency_key

    This demo uses HMAC with per-visit demo keys to keep the cryptography dependency-free. The real checker uses Ed25519. Either way, what you are seeing is tamper evidence: the check detects alteration and names the broken link. It does not prevent someone from altering their own copy.
