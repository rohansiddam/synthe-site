The commit barrier for AI agents

Synthe is the bouncer for your AI agents. Every action gets checkedcheckedverifiedscreenedchecked at the door.

Agents propose. Synthe commits. Anyone can verify. Synthe holds the credentials for real-world actions, starting with git push. It re-checks each action against a signed, human-approved plan at the moment of commit, acts exactly once if nothing has changed, and signs a receipt for every allow and every deny.

How it works

Agents propose. Synthe commits.

Most agents hold a token that can push, deploy or send. With Synthe they don't. They hand Synthe a signed proposal, and Synthe decides at the moment the action would happen.

  1. 1

    Propose

    The agent sends a typed, signed handoff, with the files it relied on pinned by hash.

  2. 2

    Approve

    A human signs the plan. The approval names the exact target, like the branch.

  3. 3

    Re-check at commit

    Synthe checks the signature, the approval, the allowed paths, and that nothing moved.

  4. 4

    Commit once, receipt always

    Synthe acts exactly once and signs a receipt, for a refusal too.

Who it's for

Built for two kinds of teams

  • 01 Engineering teams running coding agents You run two or more coding agents and won't hand them push, deploy or database credentials. With Synthe they don't need them: agents propose, a human approves, and Synthe ships the change exactly as approved.
  • 02 Teams preparing for AIUC-1 or agent insurance Auditors and underwriters ask who approved each agent action, what ran, and what was refused. Synthe records all of it as signed receipts. It produces the evidence; it doesn't make you certified, compliant or insured.

Questions, answered

What does Synthe actually hold?

The credentials for real-world actions. Today that means a GitHub token for git push. We plan to add more kinds of actions, starting with database writes and email. Your agents get a narrow way to propose an action, never the credential itself.

What's public, and what's in beta?

The handoff checker, its spec, threat model, tests and GitHub Action are public, and you can run them today. The commit broker, which holds the credentials and performs the action, is in a private beta with design partners.

Is it open source?

No. The code is public so you can read it and run it, but it's shared under an evaluation license: you may run it on your own agent workflows, but not redistribute it, publish forks, or build it into a product without our written permission.

What does it cost?

There's no price list yet. Evaluating the public checker costs nothing. If you want to pilot the commit broker, talk to us.

Does running Synthe change my code's license?

No. The evaluation license covers Synthe's code, not yours. Checking your handoffs changes nothing about how your own code is licensed.

Which agents does it work with?

Any agent that can emit JSON can send a handoff to the public checker, from the command line, from Python, or in a GitHub Action. Agent connectors come with the design-partner beta.

Do my agents have to trust each other?

No, that is the point. The receiver verifies the packet's signature against its registry and pins the evidence hashes before acting. Trust the check, not the sender.

What can't Synthe stop?

An action a human approved will do exactly what was approved; Synthe narrows a compromised agent to that one action, but can't remove it. Receipts prove which key and connector acted, not which model wrote the work. And Synthe is only a barrier if your agents can't go around it, so take their own credentials away. The full list is on the status page.

Who is building Synthe?

Co-founders Rohan Siddamsettiwar and Rishab Ramalingam, out of the University of Utah's Sandbox startup community. We built it after watching our own agents do work twice, act on stale files and take actions nobody approved.
