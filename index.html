Synthe is the bouncer for your AI agents. Every handoff gets checkedverifiedscreenedchecked at the door.

When one AI agent hands work to another, Synthe validates the handoff as a typed packet before the receiver acts. Every accepted handoff is recorded, so the same one cannot be claimed twice.

REJECT invalid: evidence_not_verbatim

Python 3 only, no install step. Exit code 0 means ACCEPT, 2 means REJECT.

How it works

  1. 1.

    The sender ships a typed packet, not a blob of text.

  2. 2.

    Synthe checks it against a registry and the actual artifacts it references.

  3. 3.

    ACCEPT records the claim. REJECT comes back with the reason, and replays of an accepted handoff are rejected as duplicates.

What this catches

  • Duplicate handoffs The same handoff arrives twice. The second copy is rejected, so the work runs once.

    REJECT duplicate_idempotency_key

  • Expired handoffs The handoff sat too long before it arrived. It is rejected instead of acted on late.

    REJECT handoff_expired

  • Stale artifacts The artifact changed after the handoff was made. Its hash no longer matches, so the handoff is rejected.

    REJECT artifact_hash_mismatch

  • Missing required fields A field the receiver needs is absent. The handoff is rejected with the gap named.

    REJECT incomplete

  • Actions the receiver is not allowed to take The handoff asks for an action outside the receiver's permissions. It is stopped before anything runs.

    REJECT authority_exceeds_receiver_policy

What changes with Synthe

Without Synthe

The receiving agent gets a blob of text and takes it on trust. It can redo work another agent already did. It can act on artifacts that changed since the handoff. It can run actions nobody approved.

With Synthe

The handoff is checked at the door, before any work starts. A bad one is stopped with a reason. A good one is recorded, so it cannot be claimed twice.

Try to break it

The repo ships one valid signed packet and eight attacks. Open each one to see the exact command and the reason it gets rejected.

$ for f in examples/v03/packets/*.json; do
$   python3 src/handoff_check.py "$f" --registry examples/v03/registry.json --workspace examples/v03/workspace --dry-run | head -4
$ done

ACCEPT once, for valid-signed.json. The other eight are REJECTs.

Tampered after signing+

The packet was altered after the signature was made, so the signature no longer matches.

$ python3 src/handoff_check.py examples/v03/packets/attack-tampered-after-signing.json --registry examples/v03/registry.json --workspace examples/v03/workspace --dry-run

REJECT signature_invalid

Spoofed sender+

The packet claims to come from an agent it isn't. The signature check fails.

$ python3 src/handoff_check.py examples/v03/packets/attack-spoofed-sender.json --registry examples/v03/registry.json --workspace examples/v03/workspace --dry-run

REJECT signature_invalid

Self-granted authority+

The sender granted itself authority that no approval covers.

$ python3 src/handoff_check.py examples/v03/packets/attack-self-granted-authority.json --registry examples/v03/registry.json --workspace examples/v03/workspace --dry-run

REJECT approval_missing

Forged approval+

The attached approval was never actually issued.

$ python3 src/handoff_check.py examples/v03/packets/attack-forged-approval.json --registry examples/v03/registry.json --workspace examples/v03/workspace --dry-run

REJECT approval_unsigned

Replayed approval+

An approval lifted from a different handoff and reused here.

$ python3 src/handoff_check.py examples/v03/packets/attack-replayed-approval.json --registry examples/v03/registry.json --workspace examples/v03/workspace --dry-run

REJECT approval_signature_invalid

Exceeds receiver policy+

The handoff asks for more authority than the receiver's policy allows.

$ python3 src/handoff_check.py examples/v03/packets/attack-exceeds-receiver-policy.json --registry examples/v03/registry.json --workspace examples/v03/workspace --dry-run

REJECT authority_exceeds_receiver_policy

Paraphrased "verbatim" evidence+

Evidence quoted loosely where the receiver required it word for word, so the hash doesn't match.

$ python3 src/handoff_check.py examples/v03/packets/attack-paraphrased-verbatim.json --registry examples/v03/registry.json --workspace examples/v03/workspace --dry-run

REJECT evidence_hash_mismatch

Undeclared actions+

The packet takes actions it never declared up front.

$ python3 src/handoff_check.py examples/v03/packets/attack-undeclared-actions.json --registry examples/v03/registry.json --workspace examples/v03/workspace --dry-run

REJECT planned_actions_missing

The keys in examples/v03/test-keys/ are public test keys. Bring your own keys for real use.

Questions, answered

  • Which agent frameworks does it work with? Any of them. The checker is dependency-free Python and a handoff is just JSON. If your agents can emit JSON, they can send handoffs.
  • What does it cost? Nothing to evaluate. Copy it, run it against your own agent workflows, and see.
  • Who is building Synthe? Co-founders Rohan Siddamsettiwar and Rishab Ramalingam, out of the University of Utah's Sandbox startup community. Say hello below!
  • Does running Synthe change my code's license? No. The evaluation license covers Synthe's code, not yours. Checking your handoffs changes nothing about how your own code is licensed.
  • Do my agents have to trust each other? No, that is the point. The receiver verifies the packet's signature against its registry and pins the evidence hashes before acting. Trust the check, not the sender.
